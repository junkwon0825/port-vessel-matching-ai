# Experiments and Validation

## 평가 기준

대회 평가식은 다음과 같습니다.

```text
0.7 × 한글 선박명 기록 정확도 + 0.3 × 비한글 선박명 기록 정확도
```

한글 기록의 비중이 작더라도 평가 가중치는 더 큽니다. 전체 정확도만 최적화하면 공식 평가식에서 불리할 수 있으므로 세 그룹의 지표를 함께 기록했습니다.

- Overall Accuracy
- Hangul Accuracy
- Non-Hangul Accuracy
- Official Weighted Accuracy

## 검증 분할

### Repeat-vessel split

학습에서 이미 본 선박의 새로운 입출항 기록을 식별하는 능력을 확인합니다.

- 검증 행: 2,678
- 정답 선박이 학습에 모두 존재
- 고유 호출부호 직접 조회 정확도: 1.0

### Unseen-vessel split

정답 선박 ID가 학습과 검증에 겹치지 않도록 분할합니다.

- 학습 행: 9,752
- 검증 행: 2,470
- 학습 선박 ID: 4,681
- 검증 선박 ID: 1,170
- 선박 ID 중복: 0

직접 조회 방식은 이 분할에서 검증 행을 커버하지 못했습니다. 이후 후보 검색과 Ranker 실험은 이 분할을 기준으로 비교했습니다.

## 후보 검색 실험

| K | Overall Recall@K | Hangul Recall@K | Non-Hangul Recall@K | 공식 가중 Recall@K |
|---:|---:|---:|---:|---:|
| 50 | 0.9364 | 0.4298 | 0.9915 | 0.5983 |
| 100 | 0.9551 | 0.5785 | 0.9960 | 0.7037 |
| 300 | 0.9947 | 0.9545 | 0.9991 | 0.9679 |
| 600 | **0.9951** | **0.9587** | **0.9991** | **0.9708** |

후보 수 300 이후 전체 Recall의 증가는 작지만, 한글 정답 누락을 줄이기 위해 최대 600개를 사용했습니다.

## Ranker 실험

| 전략 | Overall Top-1 | Hangul Top-1 | Non-Hangul Top-1 | 공식 가중 Top-1 |
|---|---:|---:|---:|---:|
| Retrieval-first | 0.8490 | 0.1901 | 0.9206 | 0.4092 |
| Ranker, unweighted | 0.8036 | 0.5537 | 0.8308 | 0.6368 |
| Ranker, official weighted | 0.7798 | 0.5785 | 0.8016 | 0.6454 |
| **Language hybrid** | **0.8870** | **0.5785** | **0.9206** | **0.6811** |

## 해석

1. Retrieval-first는 비한글 기록에서 강하지만 한글 기록을 제대로 구분하지 못했습니다.
2. Ranker는 한글 성능을 크게 높였지만 비한글 검색 순위의 강점을 일부 잃었습니다.
3. 공식 가중 학습은 한글 정확도를 높였지만 전체와 비한글 정확도가 감소했습니다.
4. 언어별 Hybrid는 한글 Ranker 결과와 비한글 검색 결과를 결합해 가장 높은 가중 점수를 기록했습니다.

## 재현성 확인

- seed 42 사용
- 입력 행 순서를 섞어도 예측 결과가 동일한지 검사
- 학습 데이터와 카탈로그 SHA-256 기록
- 모델 설정과 40개 feature 이름을 `model_metadata.json`에 저장
- 평가 서버와 동일한 상대 경로에서 모의 추론 실행

## 제한사항

- 홀드아웃은 비공개 평가 데이터의 분포를 완전히 재현하지 않습니다.
- 한글 검증 표본이 242행으로 작아 변동성이 큽니다.
- 후보 검색에서 정답이 누락되면 Ranker가 복구할 수 없습니다.
- 실제 리더보드 결과와 로컬 검증 결과를 혼동하지 않도록 구분해서 기록합니다.
